# S-PAID-1 / F1: Founder-Authored Initial Routine Fallback

This is the first bounded S-PAID-1 platform increment. It adds a model-independent route for a founder to prepare a validated initial managed routine. It does not activate hosted anonymous access, Stripe, product fulfillment, or customer UI.

The founder-only `founder-operations` action `create_manual_routine_draft` accepts `requestId`, `memberId`, `summarySentence`, `items`, and optional `founderNotes`. `items` uses the same canonical-product step shape as `publish_routine`; each submitted product name, brand, and category must match its catalog row. The caller must have a verified permanent Auth identity on the active founder allowlist. The target must have a permanent Auth identity, latest managed membership status `active`, and completed managed skin intake. The existing structural, pregnancy/prescription, and reported-sensitivity validators run before the service-only transaction.

The new `founder_create_manual_routine_draft` RPC checks those access/eligibility conditions again in the same database transaction, serializes against competing first-routine creation, creates exactly one `awaiting_review` version, and records an idempotent founder operation. A repeated request ID returns the same draft only for the same member and payload; a changed payload is rejected. A different request ID cannot create a competing initial routine. The draft enters the existing founder review queue. A separate `publish_routine` action validates again and creates an immutable published version; this action never publishes by itself. Founder notes remain protected by column privileges and are not returned to members.

The founder console now has a small create-draft form: exact-email eligibility lookup, bounded standard-catalog search, explicit AM/PM steps, and separate save/review/publish actions. Eligibility and product choices are checked again by the server; the console is only an operator aid and does not establish clinical review or formula provenance. This remains local-only until hosted migration/function deployment and readback are explicitly approved. S-OPS-1 and physical mobile acceptance remain separate release gates.
