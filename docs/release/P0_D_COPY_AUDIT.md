## Required release handoffs

1. **Separate public deployment:** `apple-site/vercel.json` provides rewrites and `apple-site/.gitignore` excludes the local `.vercel` link. There is no tracked deploy workflow or project link. After the user explicitly authorized a read-only deployment check, the portfolio root inspected the live `derive-beta-site` Vercel project through the connected project listing and an authenticated read-only project API request. The project has no connected Git repository (`link`) or production branch. Its sole READY production deployment predates this PR and records the historical `kanuj/apple-build8-external-review` branch at short SHA `1df69ab`. [Vercel's deployment documentation](https://vercel.com/docs/deployments/overview) says automatic push/merge deployment follows importing a connected Git repository. On this observed configuration, merging this source PR is not expected to publish the site; a separate deployment and live readback are required. An earlier private dashboard read was rejected by automatic approval review because that access was not then explicitly authorized. It was not retried or bypassed; the later read used the user's new authorization and a different supported read-only interface.
2. **Privacy/legal review:** Review the revised Privacy and Privacy choices text against the candidate binary, hosted processing, support operation, and intended legal commitments before public deployment. In particular, confirm the external build's AI availability, any model-provider processing, exact guest-session lifecycle and deletion reachability, and log/backup retention terms. This patch does not establish those facts.
3. **Binary and hosted acceptance:** Verify the installed candidate's Account labels and links, Support open/retry, hosted guest or managed access, exact offer and billing presentation, actual hosted deletion, adult eligibility handling, and image behavior. No source or public-page observation substitutes for those gates.
