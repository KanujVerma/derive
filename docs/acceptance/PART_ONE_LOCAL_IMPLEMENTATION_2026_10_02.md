## Source and privacy decisions

Every external policy operation remains false: Open Facts, UPCitemdb, manufacturer, DailyMed, SmartLabel and private capture. The primary worker runs catalog-first orchestration through callable Open Facts and conditional UPCitemdb identity adapters with injected transport, policy checks, bounded bodies/deadlines and per-redirect reservations. Its CLI keeps all endpoint configurations and network transport unavailable. Fixture correctness is distinct from live provider coverage. Manufacturer/DailyMed need package/NDC association and reviewed extractors before activation. No API key, paid service, provider network request, cloud photo/model fallback or real health-profile transmission was used. Existing catalog identity permission does not authorize legacy formula promotion.

Lookup, processing, retention, public/private display, hotlink/rehost/crop, attribution, export, purge obligations, policy duration and offline windows require reviewed per-source grants. Private sanitized upload destination, original/photo/transcript retention, user edit provenance and deletion derivatives remain release decisions. The complete private workflow is implemented behind disabled real-user gates: strict binary JPEG upload and full entropy validation, native metadata sanitation, owner-bound immutable upload tickets/attestations, private original OCR and attributed corrections, independent server review, atomic result/save revision checks, typed recovery and signed access, and leased Storage deletion with fresh absence verification. Check and My Stuff call the same production controller/panel. A heartbeat from the actual cleanup consumer is required before uploads are enabled; failure retracts capability. The local fixture daemon consumes cleanup every ten seconds. The standalone cleanup runner requires explicit service configuration; no hosted consumer was installed.

Operator confirmation, coverage marks and OCR confidence do not establish acceptance. The default server authority registry is empty. Only the isolated synthetic fixture registry has pinned source hashes, complete literal sections, exact package/category/variant/market association and a separately reviewed policy. Arbitrary or contradictory corrections remain partial. Correcting a declaration retracts old readiness, preserves original versus attributed edit history and obtains a new review revision. Private proof removal retains only an independently permitted original public identity; no private ingredient assertion survives. Private source policy revocation and asset expiry purge private payloads on capture, scan and saved-product reads and enqueue affected bytes for actual deletion. Review-authority withdrawal retracts accepted assertions while separately permitted originals and immutable correction history follow the private source retention policy; no revoked assertion is displayed as ready. Independently permitted facts survive. No private source is promoted to shared catalog truth.

On-device Apple Vision is replaceable and separately gated. Correction is off; no ignored customWords claim. One recognizer, six images and 4096-pixel edge are engineering limits pending phone benchmarks. The live capture review offers source images, missing-region prompts, per-line section/language, attributed corrections/originals, exact overlap assembly, and a retained same-sheet local summary. Native picker/permission/retry handlers fence capture epoch, owner and binding before and after every await. Picker/camera app-cache copies move to an opaque task-owned directory; startup purges that directory; sheet end/logout/account switch/removal/30-minute inactivity invalidate drafts and queue cleanup. Process death before Expo returns an acquisition URI can leave an SDK-owned cache copy. Broad deletion of unrelated picker caches is deliberately avoided; this narrow gap remains a physical privacy gate.
