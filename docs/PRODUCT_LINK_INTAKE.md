# Product-link intake (source candidate, not catalog truth)

This bounded source increment adds an authenticated `resolve-product-link` Edge Function. It is not yet wired into Kanuj's Check UI or deployed; a signed-build link journey remains unverified. `POST` with `requestId` (UUID) and `url`; responses are private/no-store. The function never fetches a customer-submitted URL. It recognizes exact public hosts and constructs only an official DailyMed API URL from a validated SET ID.

| Submitted link | Implemented behavior | What it does **not** establish |
| --- | --- | --- |
| `openbeautyfacts.org/product/<valid GTIN>` (including `world.`/`us.`) | Extracts the GTIN and forwards the customer's JWT and request ID to the existing owner-bound `resolve-product-identity` function. No Open Beauty Facts page, API record or photo is fetched. | A database hit, exact package, or formula merely because the URL exists. ODbL customer-facing read-through remains OFF. |
| Current `dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=<UUID>` (or `lookup.cfm`) | When `DERIVE_DAILYMED_LINK_ENABLED=true`, reserves the shared durable external-lookup budget, then makes one bounded GET to the documented `v2/spls.json` API by SET ID. Returns title, current SPL version/date and source URL as a `label_title_only` candidate. A submitted historical `version` must match the current API version or it falls back. | GTIN, exact package, ingredients, formula, FDA approval, or a personalized conclusion. Follow up with a package scan/photo or product-name search. |
| `amazon.com/dp/<ASIN>` (or known `/gp/product/` paths) | Normalizes only the ASIN and asks for a product name or label photo. `a.co`/`amzn.to` asks for an expanded link or title. | An ASIN is not a UPC, product match, formula or permission to scrape. No Amazon page, redirect, Creators API or Product Advertising API is requested. |
| Other domains | No fetch; ask for search or a label photo. | Automatic support for arbitrary retailer links. |

Security boundary: HTTPS; no embedded credentials, loopback/private literal IPs, custom ports, control characters or invalid IDs; exact host/path recognition; no input-derived network destination; redirect following disabled; response type/size/time bounded; malformed/ambiguous provider data fails closed. Source title text is untrusted, never sent as instructions to a model, and must be rendered as plain text in a future client. The fixed official API host makes submitted URL DNS resolution unnecessary; no submitted hostname is resolved or fetched. The function uses caller JWT, not service role, for the internal owner-bound resolver call. DailyMed reserves the same per-user/global lookup budget introduced by the external-candidate migration; it is disabled without a reviewed hosted budget and UI copy.

Official source: [DailyMed v2 services](https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm), [`/spls` SET ID query and JSON title/version fields](https://dailymed.nlm.nih.gov/dailymed/webservices-help/v2/spls_api.cfm). DailyMed/FDA labels are submitter-provided and do not verify a physical bottle; [openFDA data rights](https://open.fda.gov/terms/) do not by themselves authorize third-party images or exact-formula claims. Amazon permissions remain as reviewed in [external source evaluation](EXTERNAL_CATALOG_SOURCE_EVALUATION.md).
