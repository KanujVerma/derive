# Ingredient-panel attempts — local candidate

2026-10-17. The approved bounded milestone is two ingredient-panel submissions per scan session: one initial attempt and one guided retake. Client recovery and durable server enforcement are implemented and verified locally. Photo recognition, hosted activation and device acceptance remain open.

## Implemented behavior

- Check owns one in-memory `ingredientPanelSession`, shared with the existing capture host and bridge. Recovery remounts, role changes, photo replacement, foreground resume and result dismissal do not replenish its budget. Explicitly opening a new scan, selecting a new customer Check from entry search, receiving a new barcode scan, or changing the current owner starts a new generation. Same-Check photo/link/name recovery retains its scope; dismissing a result alone does not reset it. Ending Check discards the in-memory session.
- A unique submitted ingredient photo reserves an attempt synchronously before processing. Preview-only retakes, front-label photos, packaging and barcodes do not consume ingredient attempts. A repeated submitted local photo URI is rejected without another dispatch; concurrent panels cannot reserve the second slot while the first is pending. Local URI identity is a UX deduplication key, not a cryptographic image identity or server authorization.
- The first failure offers one new ingredient-panel photo with allowlisted guidance. Unreadable text, conflicting evidence, a missing panel and incomplete coverage have distinct instructions. An unavailable or unconfirmed result uses qualified guidance without claiming an observed optical defect. Current producers do not supply optical quality findings; those detailed branches are synthetic test coverage.
- The bridge forwards an ingredient result only when the existing canonical snapshot predicate confirms a verified formula for the selected package. Candidate labels, formula-only matches, missing formulas, contradictions and arbitrary OCR ingredients cannot satisfy that predicate. Failed ingredient attempts do not hand off an incomplete-formula verdict or create a human-review route. Existing supported facts remain separate.
- After the second failure, the capture controls are replaced by **Use product link**, **Search verified catalog**, and **Retry later**. Search shortlists catalog summaries with an available verified variant formula; the customer still chooses the exact product/size/variant and the existing Check resolver establishes any authority. A shortlist is not package verification. No match remains unknown. Retry later closes capture; it schedules nothing and does not automatically replenish the session.
- Attempt tickets, processing sequence and scan generation fence pending and completed results. Native and in-screen close synchronously retire processing/delivery; background handoffs carry a generation and are discarded after a session reset. A canceled or unavailable submitted attempt keeps its charge because completion cannot establish that no work occurred.

## Durable server enforcement — local candidate

The Check-owned session now retains a stable `scanSessionId` UUID across capture remounts and guided retakes. The existing live free-photo and ingredient-continuation processors send it with ordinary Scan identity requests as well as each ingredient panel; barcode-link fallback forwards it internally. A deliberate new scan or owner change creates a new UUID; this is per-scan accounting, not a new account-wide quota.

`resolve-product-identity` authenticates the owner and verifies the existing private-object grant and stored object before reserving work. Both ordinary Scan ingredient photos and `continue_ingredients` use the same service-only reservation boundary. Front labels, packaging, barcode and Shelf behavior do not consume this ingredient budget. An ingredient request requires one panel and its scan UUID, and rejects mixed client OCR/transcription. The text-only continuation's existing authority and immutable-child contract are preserved.

The new migration adds owner-scoped sessions, immutable scan aliases and a maximum of two attempt rows. Atomic reservation locks the existing Check root when present, then the owner/scan alias key and journal. The trusted S6 writer retains the originating scan in the case's evidence metadata when identity is created. A noncharging bind associates an eligible root before return; the reservation also recovers that metadata after an interruption before the bind. This preserves earlier charges even when the client UUID changes before its first continuation. Binding the first Check root adopts prior standalone charges. Reopening that root under another client UUID stores an alias, including busy/exhausted replies; omitting the root later cannot create a fresh budget. A conflicting already-started scope is rejected rather than discarding its charges. Request/payload conflicts, duplicate granted object paths, concurrent submissions and response-loss retries cannot create extra slots. Object-path fingerprints identify granted evidence, not image-content equivalence.

A reservation is charged before decoder work. It is never refunded after failure or interruption. An expired 60-second lease becomes terminal unavailable and permits only the remaining slot; an old token cannot overwrite that result or settle a newer permit. Server receipts reconcile tentative client counters, so an uncharged busy/duplicate response does not consume the real remaining permit. Local generation/owner fences still reject retired responses. Owner or bound-root deletion cascades sessions, aliases and attempts; all three tables have RLS and no anonymous/authenticated access, and only the service role can invoke the security-invoker RPCs. No Auth, Storage or deletion policy is weakened.

Failed photos return a strict `ingredient_panel_attempt` processing receipt with request/session/parent binding, an allowlisted reason and, after exhaustion, product-link / verified-catalog / retry-later actions. They create no S6 child or truth snapshot, ingredients, personalized verdict or human-review route. The existing provider-neutral decoder is unchanged. Synthetic injected observations verify clearer-photo / another-angle reasons; candidate identity remains unconfirmed and OCR ingredient text is discarded at this boundary.
