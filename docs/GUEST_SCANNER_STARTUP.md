# Hosted scanner guest startup candidate — 2026-10-04

The exact production scanner shell now uses the same startup as the free local shell: check the persisted Supabase session, reuse its owner (guest or permanent), and call signInAnonymously only if no session exists. The existing helper single-flights concurrent starts. Lookup, creation or mismatched-user errors fail closed. The root waits for Auth, then matching access-state and canonical owner context; the optional profile intro can still be skipped. Startup failure uses the existing connection/retry screen with no automatic retry loop. Legacy production/staging shells remain under their previous routing. No RLS, JWT, membership, source gate or server credential change.

Supabase session persistence and auto-refresh already exist. Anonymous owners remain real authenticated owners with UUID/JWT and private owner-scoped data. Closing/relaunching can reuse retained credentials; reinstall, cleared storage or a new device may lose recovery. Existing guest account replacement guards stay active. Same-UUID account linking and automated guest retention/cleanup are not implemented by this change.
