# Part 3 local release cards

These cards describe the bounded original synthetic engineering release `part-three-local-v1`. They do not approve scientific claims, source rights, processing, a model job or production activation. Product, evidence, privacy and engineering reviewers are **unassigned; approval pending**. A code tag, passing fixture or existing field named `reviewed` is lineage, not an independent review decision.

The authority is the [Part 3 design specification](../../inputs/spec-full.txt), especially sections 2–4, 6–8 and 13. Implementation sources are [release.ts](../src/domain/part-three/release.ts), [projection.ts](../src/domain/part-three/projection.ts), [evaluate.ts](../src/domain/part-three/evaluate.ts), [copy.ts](../src/presentation/part-three/copy.ts) and the strict [result contract](../src/contracts/PersonalResultV2.ts). These files are under active local engineering; changes to a proposition, predicate, copy argument, mapping or suppression policy require a new reviewed card/release version before activation. This document does not silently broaden the runtime.

Predicates return eligible, inapplicable or insufficient with a reason. Missing input is not a false/no answer. Unknown, expired, revoked, foreign, unbound-for-that-proposition or materially conflicting inputs cannot support the conclusion. Every card depends on its exact source/field/fact/occurrence and active context revisions, dictionary/card/release epochs, owner/account generation and earliest lease. ## Question cards

Common version=`material-question-v1`. Required answer schema preserves unsure/withheld/unanswered, and skip is a separate suppression event. First visible exposure or accessibility announcement latches ID; answer, invalidation, refresh and reopen cannot create a second automatic question. Skip is durable encounter suppression; withholding persists for that field across encounters until explicit change. Withdrawal/removal invokes removal, not “no”. Intent/comparator are encounter-scoped; profile/routine answers require clear durable controls and acknowledged CAS against actual base revision, retaining draft on failure.

## Withdrawal and coverage ledger

All cards are bounded by input/field permission and reverse dependencies to current results, template arguments, optional menus/provider traces, saved assessments, working memory and visible clients. Source/field expiry or withdrawal invalidates affected facts; report/note erasure must purge original V1/V2 bytes and dependent enums/prose, not merely hide UI. Corrected active report supersedes, rather than adds an independent experience. A surviving permitted proposition should be recomputed. Offline TTL alone cannot authorize current personal judgment. No provider retention/deletion promise is inferred from local erasure.

Local release coverage: exact preference/sensitivity matches in the bounded dictionary; selected manual/report-qualified recall; one selected current practical comparison; helpful/mixed/not-helping and unknown report states; add/replace/current intent; partial/source-only/conflict/unknown limits. Clinical efficacy comparisons, reproductive clearance, generalized interactions, ingredient causal overlap, whole-routine optimization, broad product/catalog coverage and note interpretation are excluded. Full expected packet/copy/dependency fixtures and current usability gaps are tracked in [the acceptance review](../../acceptance-gap-review.md). No held-out utility, actual customer reach, independent scientific review or production readiness is claimed.
