## Implementation boundary

`supabase/functions/_shared/upcitemdb-candidate.ts` implements one barcode-only, internal-evaluation candidate adapter. It is **not called by Check or any Edge endpoint**. The module defaults to OFF, accepts only valid GTINs, and requires an explicit durable request-reservation callback before network access. It supports no-key trial and server-header paid-key modes, a 3-second maximum timeout, 64 KiB response bound, no redirects/retries, exact UPC-A/zero-prefixed EAN-13 equivalence, and exact GTIN-14 pack matching. Multiple results stay ambiguous. It returns only bounded title/brand/size/category identity fields with source provenance and `formulaVerified: false`; it discards provider images, descriptions, offers, ingredients and all raw response data. It must never write canonical products, formula, private Check history, or a public cache.

`DERIVE_UPCITEMDB_EVALUATION_ENABLED` (leave unset/empty, equivalent to OFF) and optional server-only `UPCITEMDB_API_KEY` are documented in `supabase/.env.example` for a later server caller. **Setting either value today does not connect or activate the module.** Do not paste a paid key into Expo/`EXPO_PUBLIC_*`, logs, tests, or GitHub. For a future endpoint, reuse a durable owner/global reservation such as the OBF budget only after the budget is made source-aware; do not let two providers spend from an unreviewed shared quota or exceed UPCitemdb's trial burst/sustained limits. The free Explorer pool has no key and appears IP-scoped, so it is not suitable as an unmetered customer production fallback.

## Before any paid or public activation

1. Freeze and privately adjudicate the same 20–30 Target pilot barcode encounters, then expand to the required 50+ cross-retailer/category set before a release decision. Run each permitted provider on the same denominator. Score exact package/variant, product-family-only, ambiguous, confidently wrong, no match, ingredients available, latency and cost per *useful* hit; distinguish direct and photo-assisted outcomes. UPCitemdb's marketing database-row count is not a hit rate.
2. Obtain written answers from UPCitemdb and Barcode Lookup for consumer display in a free/paid iOS skincare app, which exact fields may be stored, TTL/cache and backup/deletion terms, image/description rights, benchmark/scripted access, data provenance/correction, and termination. For UPCitemdb, ask whether published free Explorer terms permit a 50-product nonpublic scripted benchmark and whether DEV's daily/minute/overage limits fit launch traffic. No purchase or new agreement is implied here.
3. Choose a provider from observed **incremental useful-scan lift** over Derive's internal canonical path and total rights/operating cost, not advertised row count or headline calls per dollar. Put it behind a reviewed server-only feature flag, real per-source reservation/circuit breaker, auth, privacy and attribution surface. Candidate identity still must not become verified formula truth.
4. Reconcile source permissions, retention/deletion, provider spend ceiling, and exact hosted rollout in one reviewed activation change. No customer-facing activation follows from merging this module.

The separate external-source evaluation in PR #163 also covers OBF/ODbL, Amazon, and Scandit. This packet is additive and deliberately does not weaken those gates.
